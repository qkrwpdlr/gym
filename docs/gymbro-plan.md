# gymbro 기획서 — GYM PWA 확장 계획

> 작성: 2026-06-11. 멀티에이전트 설계(데이터 모델 / 서버 / UX / LLM 인터랙션 4개 영역 병렬 설계 + 교차 검증)를 종합한 정본 기획.
> 이 문서의 결정이 이후 구현의 기준이다. 재논의가 필요하면 이 문서를 갱신한다.

## 1. 비전

기존 5일 분할 체크리스트 PWA를 **LLM 코치(gymbro)가 붙은 트레이닝 앱**으로 확장한다.

1. **당일 조정 챗** — 오늘 루틴 화면의 플로팅 버튼(FAB)으로 챗을 열고 "오늘 컨디션 별로야"라고 하면, gymbro가 오늘 루틴과 최근 기록을 보고 조정안을 제안. 수락하면 오늘에만 적용(원본 비파괴).
2. **프로그램 빌더** — 대화로 4주/6주 블록 단위 프로그램을 생성·개편. 쌓인 운동일지가 다음 블록 설계의 참고자료가 된다.
3. **기록 체계** — 목표가 아닌 **실측 무게/횟수**를 세트별로 기록하고, 운동일지를 달력 UI로 조회.
4. **범용 주간 구조** — D1~D5 고정에서 주 2~7회 어떤 빈도든 수용하는 구조로 일반화.

전략: **PWA에서 전부 검증 → 이후 SwiftUI 네이티브 전환.** LLM은 **DeepSeek API**, 서버는 LLM 프록시 1개(비용 최소, 무단 사용 차단).

## 2. 정본 결정 (설계 충돌 5개 축의 최종 판정)

병렬 설계 과정에서 상호 배타적인 결정이 병존했던 지점들. 아래가 최종 결정이다.

| # | 쟁점 | 결정 (v1) | 업그레이드 경로 |
|---|---|---|---|
| 1 | 프로그램 표현: 전 주차 완전 전개 vs 템플릿+규칙 | **1주 템플릿 + `linear_kg` 진행 규칙 + 디로드 1개.** 주차 무게는 렌더 시 계산(전개 저장 없음). LLM 출력도 이 형태(4~8K 토큰으로 작음) | 주차별 개별 편집이 필요해지면 전개 저장(materialize)으로 승격 |
| 2 | 세트 주소: UUID(setId) vs 배열 인덱스 | **LLM 와이어는 스냅샷 기준 s/i 인덱스.** 수락 시 클라이언트가 ops를 1회 적용해 **유효 day 스냅샷 전체를 저장** — ops/ID 영구 보존 안 함 | 조정 히스토리 분석이 필요해지면 ops 병행 저장, 동기화 시점에 setId 도입 |
| 3 | LLM 응답 계약: function calling vs JSON 모드 | **JSON 봉투 단일 경로**: `{"message": "...", "proposal": {...}\|null}`. 모델 무관 동작, 파서 1벌 | flash의 tool calling 지원 확인 + 봉투 파싱이 말썽일 때 function calling으로 교체(내부 표현 동일, 파서만 교체) |
| 4 | 저장소: IndexedDB vs localStorage | **localStorage 유지, `gym-v4-` 프리픽스 통일.** 일지는 날짜 키 + 인덱스 배열. (주 5회×1년 ≈ 2MB, 한도의 30%) | 용량 80% 도달 또는 서버 동기화 시점에 IndexedDB/서버로 이전 (레코드 구조 1:1 매핑됨) |
| 5 | 스트리밍: SSE vs 비스트리밍 | **비스트리밍 fetch + 로딩 인디케이터.** 당일 조정 응답은 1~3문장(2~4초). JSON 봉투와 SSE는 궁합도 나쁨 | 빌더 생성 대기(30~90초)가 고통스러우면 그 호출만 SSE 추가 |

공통 원칙(전 단계 불변):
- **모델은 절대 직접 적용하지 못한다. 적용 주체는 항상 사용자의 수락 탭.**
- **시스템 프롬프트·model id·max_tokens·thinking은 서버에만 존재** — 클라이언트가 덮어쓸 수 없다.
- 원본 프로그램은 비파괴. 당일 조정은 날짜 키 오버라이드 레이어로, 날짜가 지나면 자연 만료.

## 3. 아키텍처

```
┌─ PWA (GitHub Pages, 단일 index.html 유지) ────────────────┐
│  오늘 탭(루틴+실측 기록+FAB 챗) / 기록 탭(달력) / 설정 탭   │
│  localStorage: gym-v4-program, gym-v4-log-*, gym-v4-override-* │
└──────────────┬───────────────────────────────────────────┘
               │ POST /v1/chat  (Bearer 디바이스 토큰)
┌──────────────▼───────────────────────────────────────────┐
│  Cloudflare Worker (무료 플랜, 1파일 ~100줄)               │
│  CORS 고정 → 토큰 해시 검증 → 본문 캡 → 파라미터 서버 고정  │
└──────────────┬───────────────────────────────────────────┘
               │ POST https://api.deepseek.com/chat/completions
┌──────────────▼───────────────────────────────────────────┐
│  DeepSeek deepseek-v4-flash (JSON 모드, 자동 컨텍스트 캐시) │
└──────────────────────────────────────────────────────────┘
```

### 호스팅 결정: Cloudflare Workers (EC2 기각)

| 비교 축 | **CF Workers 무료** | Lambda+Function URL | EC2 t4g.nano |
|---|---|---|---|
| 월 비용(일 10~30회 호출) | **$0** (한도 100k req/일) | ~$0~1 (신규 계정 무료 플랜은 크레딧 기반) | ~$7~8 (인스턴스+EBS+IPv4) |
| 유휴 비용 | 0 | 0 | **24시간 과금** |
| 운영 부담 | `wrangler deploy` 한 줄 | IAM 등 중간 | OS 패치·TLS·복구 전부 직접 |
| 콜드스타트 | ~0ms (V8 isolate) | 100~500ms | 없음 |

하루 30회 호출에 상시 인스턴스는 최악의 적합도. EC2 대비 연 ~$90 절감. Cloudflare 계정도 이미 연결돼 있음.

## 4. 데이터 모델 (v1)

저장 키는 전부 `gym-v4-` 프리픽스. 순수 JSON(향후 Swift `Codable`/서버 직렬화 호환), 날짜는 로컬 달력일 `"YYYY-MM-DD"`, 시각은 ISO8601.

### 4.1 Program (블록)

```jsonc
// gym-v4-program (활성 1개), 종료된 블록은 gym-v4-program-archive 배열로 이동
{
  "schemaVersion": 1,
  "id": "prog_8f3a1c2e",
  "name": "여름 스트렝스 블록",
  "intent": "스쿼트 180x3 → 185x3. 3주 축적 + 4주차 디로드",
  "startDate": "2026-06-15",
  "weeks": 4,
  "daysPerWeek": 5,
  "createdAt": "2026-06-11T09:00:00+09:00",
  "days": [            // 1주 템플릿. 기존 ROUTINE 스키마와 거의 동일 → 렌더러 재사용
    {
      "slot": 1,
      "weekday": "MON",   // null 허용 — 요일 비고정(주 N회만 지키는) 사용자 지원
      "title": "SQUAT + BENCH",
      "tag": "HEAVY SQUAT · BENCH VOLUME",
      "color": "#ff2d2d",
      "sections": [
        { "title": "스쿼트 탑셋", "meta": "RPE 8", "rest": 300,
          "sets": [ { "label": "TOP", "name": "로우바 스쿼트", "weight": "180", "unit": "kg", "reps": "3" } ] }
      ]
    }
  ],
  "progression": [     // 규칙은 v1에서 linear_kg 1종만
    { "dayIdx": 0, "sectionIdx": 1, "rule": "linear_kg", "perWeek": 2.5 }
  ],
  "deload": { "week": 4, "weightFactor": 0.85, "setDrop": 1 }   // 전역 1개 또는 null
}
```

- **주차 무게는 렌더 시 계산**: `round2.5(parseWeight(base) + perWeek × (week-1))`, 디로드 주는 factor 적용. 전개본을 저장하지 않으므로 프로그램 객체가 단일 진실.
- `weight`는 현행 문자열 유지(`"180"`, `"BAR"`, `"BW"`, `""`). 톤수·진행 계산용 `parseWeight()` 헬퍼 1개로 흡수. (number/weightText 필드 분리는 네이티브 전환 시점에.)
- `'BAR'|'BW'` 등 비숫자 weight는 progression 대상 불가 — 검증에서 거부.
- 현재 주차: `floor((오늘 - startDate)/7일) + 1`. 오늘 탭 헤더에 `WEEK n/m` 표시.
- **마이그레이션**: 별도 절차 없음. `routine.js`의 `ROUTINE`은 "활성 블록 없을 때의 기본 템플릿"으로 강등(폴백 유지). 기존 `gym-v3-*` 체크 상태는 배포일에 1회 리셋(휘발성 데이터라 손실 없음).

### 4.2 SessionLog (운동일지)

```jsonc
// gym-v4-log-2026-06-15  +  gym-v4-log-index = ["2026-06-15", ...] (날짜 배열)
{
  "schemaVersion": 1,
  "date": "2026-06-15",
  "programId": "prog_8f3a1c2e",   // 없으면 null (routine.js 폴백 운동)
  "week": 1,
  "daySlot": 1,
  "dayTitle": "SQUAT + BENCH",
  "color": "#ff2d2d",
  "startedAt": "2026-06-15T18:05:00+09:00",
  "endedAt": "2026-06-15T19:40:00+09:00",
  "note": "탑셋 바속도 빨랐음. 허리 약간 뻐근.",   // 세션 메모(컨디션 포함) — LLM 핵심 컨텍스트
  "adjusted": "탑셋 -10%, 보조 1개 제거 (컨디션)",  // 그날 오버라이드 요약 (없으면 null)
  "sets": [
    { "s": 1, "i": 0, "name": "로우바 스쿼트", "label": "TOP",
      "targetW": "180", "targetR": "3",
      "actualW": "180", "actualR": "3",
      "done": true, "skipped": false, "rpe": 8 }
  ]
}
```

- **체크 = 목표값을 실측값으로 자동 복사.** 계획대로 했으면 추가 입력 0회. 다르게 했을 때만 수정(§6.2).
- **skipped 의미 고정**: `skipped: true`는 진행상 통과(다음 세트로 이동)하되 **done 집계·달력 완료율에서는 제외**, actual은 null.
- target은 **오버라이드 적용 후 유효 목표** 기준(자기완결 — 프로그램을 나중에 지워도 일지는 그대로 읽힘).
- 달력 월뷰: `gym-v4-log-index`에서 해당 월 날짜만 골라 개별 파싱(월 ~30건, 체감 0ms).
- v1은 1일 1세션 전제(이중 분할 운동은 백로그).

### 4.3 DayOverride (당일 조정)

```jsonc
// gym-v4-override-2026-06-17
{
  "schemaVersion": 1,
  "date": "2026-06-17",
  "daySlot": 3,
  "effectiveDay": { /* 조정이 적용된 day 스냅샷 전체. 변경 세트에 "_changed": true */ },
  "summary": "탑셋 -10%, 데드 백오프 1세트 축소",
  "reason": "수면 4시간 + 허리 뻐근",
  "changes": ["데드 탑셋 220→200", "백오프 B3 제거"],   // diff 카드·배지 표시용
  "appliedAt": "2026-06-17T17:50:00+09:00",
  "revoked": false                                       // [원본으로 되돌리기] = true
}
```

- 렌더 규칙: `오늘 키에 오버라이드가 있고 !revoked → effectiveDay, 아니면 템플릿(주차 계산 적용)`. if문 1개.
- **자연 만료**: 조회 키가 오늘 날짜이므로 날짜가 지나면 자동으로 적용 대상에서 빠진다. 레코드는 보존(adjusted 요약의 원천).
- 같은 날 재조정: 현재 유효 루틴 스냅샷 기준으로 새 제안을 받고 **스냅샷 교체 + reason append** (1일 1레코드).
- **운동 중 조정 시 체크 보존**: 오버라이드 적용 직후 진행 중 세션 로그의 세트들을 `(섹션 title + 세트 label/name)` 매칭으로 새 스냅샷에 리매핑. LLM에는 "done 세트 수정 금지"를 프롬프트로 강제.

## 5. 서버 설계 (Cloudflare Worker, 1파일)

### 5.1 API — `POST /v1/chat` (라우트 1개)

```jsonc
// 요청  (Authorization: Bearer <device-token>)
{
  "mode": "daily_adjust" | "program_intake" | "program_generate",
  "messages": [ { "role": "user" | "assistant", "content": "..." } ]
  // system role은 400. 컨텍스트(오늘 루틴 스냅샷+기록 요약)는 클라이언트가
  // 첫 user 메시지에 직접 포함 — 서버는 stateless, 별도 context 필드 없음
}
// 응답: DeepSeek 응답의 content(JSON 봉투 문자열)와 usage만 추려서 반환
```

**mode별 서버 고정 프리셋** (클라이언트가 model/max_tokens/thinking을 보내면 400):

| mode | thinking | max_tokens | 용도 |
|---|---|---|---|
| `daily_adjust` | disabled (즉답) | 2,048 | 당일 조정 대화+제안 |
| `program_intake` | disabled | 1,024 | 빌더 인테이크 문답 |
| `program_generate` | **enabled** (설계 품질) | 16,384 | 블록 최종 생성 |

모든 mode가 `response_format: {type:"json_object"}` + 서버 측 시스템 프롬프트(mode별) 주입. 메시지 순서는 [system(정적) → 컨텍스트(세션 내 정적) → 대화(append-only)]로 고정 — DeepSeek 자동 prefix 캐시 히트($0.14 → $0.0028/M).

에러: `401` 토큰 무효 / `403` Origin 불일치 / `400` 스키마 위반 / `413` 본문 128KB 초과(빌더 수정 턴의 블록 JSON 감안) / `429` DeepSeek 한도 / `502` 업스트림 장애.

### 5.2 무단 사용 차단

1. **디바이스 토큰**: 로컬에서 `openssl rand -base64 32` 생성 → **SHA-256 해시만** Worker Secret에 저장. 원문은 앱 설정 화면에 1회 입력 → `gym-v4-api-token`(localStorage) → 매 요청 Bearer. 서버는 타이밍세이프 해시 비교. 틀린 요청은 즉시 401 — 봇 스캔이 비용을 만들 수 없음.
2. **CORS 고정**: GitHub Pages 오리진 1개만 허용. SwiftUI 네이티브는 Origin이 없으므로 토큰만으로 통과 — 전환 시 코드 변경 불필요.
3. **서버 단독 권한**: 시스템 프롬프트·model·max_tokens·thinking 전부 서버 고정.
4. **절대 손실 상한**: DeepSeek **선불 잔액을 $5~10로 유지** — 서버 로직이 뚫려도 손실은 잔액까지. (KV rate limit 카운터는 v1에서 생략, 이상 트래픽 관찰 시 ~20줄 추가)

### 5.3 비용 추정

인프라 $0 (Workers 무료 플랜). LLM(deepseek-v4-flash, $0.14/M 입력·$0.28/M 출력, 캐시 히트 $0.0028/M):

| 시나리오 | 월 호출 | 월 비용 (전량 캐시 미스 상한) |
|---|---|---|
| 일 10회 | 300 | **~$0.21** |
| 일 30회 | 900 | **~$0.63** |
| 현실 사용(조정 20회 + 블록 1회/월, 캐시 히트 반영) | — | **~$0.05 미만** |

## 6. LLM 설계 (gymbro)

### 6.1 응답 계약 — JSON 봉투

모든 모드에서 모델은 아래 JSON만 출력한다 (DeepSeek JSON 모드 요건: 프롬프트에 "json" 단어 + 형식 예시 포함):

```jsonc
// daily_adjust / program_intake
{ "message": "대화 텍스트 (한국어 반말)", "proposal": null }
// 조정 제안이 있을 때
{ "message": "그럼 오늘은 이렇게 가자.",
  "proposal": {
    "summary": "탑셋 -10%, 백오프 1세트 축소",
    "reason": "수면 부족 + 허리 피로",
    "ops": [
      { "op": "update_set",     "s": 1, "i": 0, "patch": { "weight": "162.5", "reps": "3" } },
      { "op": "remove_set",     "s": 2, "i": 3 },
      { "op": "add_set",        "s": 3, "after": 2, "set": { "label": "S4", "name": "스티프 데드", "weight": "100", "unit": "kg", "reps": "10" } },
      { "op": "update_section", "s": 1, "patch": { "rest": 360 } },
      { "op": "remove_section", "s": 4 }
    ]
  } }
// program_generate
{ "message": "블록 설계 끝났어. 미리보기 봐봐.", "program": { /* §4.1 Program 스키마 그대로 */ } }
```

- `s`/`i`는 **클라이언트가 컨텍스트로 보낸 유효 루틴 스냅샷 기준 인덱스** (스냅샷 JSON에 s/i를 명시 포함 — 모델이 위치를 세지 않게 해 오프바이원 방지).
- 클라이언트는 ops를 **인덱스 내림차순으로 1회 적용** → effectiveDay 스냅샷 생성 → §4.3 형태로 저장. ops 자체는 버린다.
- 수락/거절 결과는 다음 user 메시지 한 줄로 전달("적용했어" / "거절: 무릎 때문에") — tool role 관리 불필요.

### 6.2 당일 조정 챗 플로우

1. FAB 탭 → 풀스크린 챗. 첫 요청에 클라이언트가 컨텍스트 블록 구성:
   - 오늘의 **유효 루틴** compact JSON (오버라이드·체크·실측 상태 합성, s/i 명시)
   - **히스토리 요약** (§6.4, 로컬 계산)
2. 모델이 1~2개 되묻거나 바로 `proposal` 반환 → **diff 카드** 렌더 (`180 → 160` 형식, 변경=노랑/삭제=빨강/추가=초록) + [적용]/[거절].
3. 적용 → 오버라이드 저장, 토스트, 루틴 화면에 `⚡ 오늘 조정됨` 배지(+탭하면 diff 목록과 [원본으로 되돌리기]).
4. 챗 히스토리는 메모리만(시트 닫으면 세션 종료). 체육관 대화는 3분짜리다.

### 6.3 프로그램 빌더 플로우

- **Phase A 인테이크** (`program_intake`): 목표(스트렝스/비대/혼합), 주당 일수(2~7), 장비, 메인리프트 현재 수준(기록 요약 값을 제시하고 확인만), 블록 길이(4/6주), 통증·시간 제약. 한 번에 하나씩 질문 → 설계 방향 요약 → 동의.
- **Phase B 생성** (`program_generate`, thinking on): §4.1 Program JSON 출력. 출력 전략은 "1주 템플릿+진행 규칙"이라 4~8K 토큰, 1~2분 내 완료. "블록 설계 중…" 진행 화면 + 180초 타임아웃.
- **검증** (클라이언트, 의존성 없는 수제 밸리데이터): 필수 필드·타입 → `days.length === daysPerWeek` → weight 형식 → progression 대상이 숫자 weight인지 → 전 주차 무게 계산 시도. 실패 시 자동 루프 없이 "생성이 꼬였어, 다시 요청해줘" 카드 + [재시도].
- **적용**: 텍스트 요약 + day별 제목 리스트 미리보기 → [이 블록 적용] → 확인 모달(시작일 선택) → 기존 블록은 archive로, 오늘 탭은 새 블록 W1로.

### 6.4 히스토리 요약 (LLM 호출 없음, 순수 로컬 계산)

`buildHistorySummary()`: 최근 12세션 로그 →
- 메인리프트 매핑(이름 정규화 → SQ/BP/DL/OHP)별: best e1RM `max(w×(1+r/30))` (actual 우선), 최근 탑셋, 4세션 추이(↑/→/↓)
- 수행률(done세트/계획세트 %), 최근 3세션 note + adjusted

출력은 압축 텍스트 (목표 500~800토큰, 초과 시 8세션으로 축소):

```
== 최근 12세션 요약 (05-04~06-10) ==
SQ: e1RM 198kg (→). 최근탑셋 06-09 180×3@RPE8. 백오프 160×5×4 완수.
DL: e1RM 244kg (↓ -4). 최근탑셋 06-03 220×1@RPE9. 백오프 3→2세트 축소함.
수행률: 최근4세션 평균 91%.
메모: 06-09 "무릎 시큰" / 06-03 "허리 뻐근, 수면 5h" (당일 조정: 데드 백오프 1세트 삭제)
```

당일 조정 챗과 빌더 양쪽에서 동일 함수 재사용.

## 7. UX/UI 설계

디자인 언어는 현행 유지: 다크(`#0a0a0a`) + 요일별 accent + Bebas Neue(큰 숫자) / JetBrains Mono(라벨) / Noto Sans KR(본문). 색 의미 체계를 전 화면으로 확장 — **빨강=주 액션, 노랑=타이머·"계획과 다름"(조정/실측 차이), 초록=완료**.

### 7.1 내비게이션 — 하단 탭 3개 + day 칩 스트립

```
[ TODAY ]  [ LOG ]  [ CONFIG ]      ← 기존 .tab 구조(mono 캡션+Bebas+dot) 재사용
```

- **D1~D5 하단 탭 폐기.** day 선택은 오늘 화면 안의 가로 칩 스트립으로 이동 — 주 2회면 칩 2개(균등 배치), 7회면 가로 스크롤+페이드. 이것이 주 2~7회를 전부 견디는 유일한 구조.
- 라우팅: `#/today/:slot`, `#/log`, `#/log/:date`, `#/settings`. 기존 `#/day1~5`는 리다이렉트. **현행 라우터는 미인식 해시를 day로 폴백시키므로 경로 테이블 방식으로 교체 필수.**
- 오늘 화면 헤더: `◆ WEEK 2/4 · HEAVY SQUAT` (주차 표시 추가), 조정된 날엔 `⚡ 오늘 조정됨` 노랑 배지.
- 기본 선택 day: ①오늘 요일에 스케줄된 day → ②이번 주 첫 미완료 → ③slot 1.
- 빌더 진입은 설정 탭 안 `[✦ 다음 블록 만들기]` 버튼 → 풀스크린. (코치 탭/대시보드는 백로그 — 기록이 8주쯤 쌓인 뒤가 적기.)

### 7.2 실측 기록 입력 — "계획대로 했으면 추가 입력 0회"

**체크리스트 모드**: 세트 행을 터치 영역 2개로 분할.

```
[✓] B2  | 160 KG · 5 |     ← 좌측(체크박스+라벨) 탭 = 체크 토글 (기존 그대로, 목표=실측 자동 기록)
                            ← 숫자 영역 탭 = 실측 편집 바텀시트
수정된 행: [✓] B2  ̶1̶6̶0̶ 152.5 KG · 5  ●   ← 실측을 노랑으로, 목표는 취소선 병기
```

**실측 편집 시트** (공용 컴포넌트, 한 손 도달 범위):

```
로우바 스쿼트 · B2
[−2.5]  152.5  [+2.5]     ← Bebas 64px, 숫자 탭=숫자패드
[ −1 ]    5    [ +1 ]
RPE (7)(7.5)(8)(8.5)(9)(10)  ← 선택 안 해도 됨
[스킵]            [기록 ✓]
```

**집중(FOCUS) 모드**: 큰 `DONE·NEXT` 버튼은 그대로 "계획대로" 경로(목표=실측+휴식 진입). 그 위에 가는 보조 버튼 `┄ 다르게 했어요 ┄` 1개 → 실측 시트 → 기록 시 체크+휴식 진입. (휴식 화면 내 수정은 v1 생략 — 체크리스트에서 언제든 수정 가능.)

### 7.3 기록(LOG) 탭 — 월 달력

```
◀ 2026. 06 ▶
일 월 화 수 목 금 토
    1● 2  3● 4  5● ...     ← 도트 = 그날 수행한 day의 색, 부분 수행 = 반투명
── THIS MONTH ──  출석 11일
── 6/11 (수) ──            ← 날짜 탭 → 하단 인라인 카드
DAY 03 · DEADLIFT  ⚡조정됨
21 SETS · 52분  [세션 상세 →]
```

세션 상세(`#/log/:date`): 기존 section/set-row 컴포넌트 재사용(읽기전용). 목표 vs 실측 차이는 노랑, 스킵은 dim, 하단에 조정 내역(`adjusted`)과 세션 메모. (주 뷰·볼륨 차트는 백로그.)

### 7.4 FAB + 챗

- **FAB**: 우하단 고정 56px 원형 accent, `bottom: 탭바 위 + safe-area`. **오늘 탭에서만 노출**, 휴식 타이머 오버레이가 떠 있으면 숨김(겹침 회피 끝). 미적용 제안이 있으면 노랑 배지 도트.
- **챗 화면**: v1은 고정 풀스크린 오버레이(FAB 탭→열림, X→닫힘). 빈 상태에 퀵 칩: `(컨디션 별로)` `(시간 30분뿐)` `(허리 불편)` `(어제 과음)`.
- **diff 카드** (챗 버블 내, 노랑 좌측 보더):

```
┌ 제안된 조정 ⚡ ───────────┐
│ 스쿼트 탑셋  ̶1̶8̶0̶ → 160   │
│ 백오프      4세트 → 3     │
│ − 레그 익스텐션 (제외)     │
│ [ 적용 ]      [ 거절 ]    │
└──────────────────────────┘
```

- 적용 → 토스트 "오늘 루틴에 적용됨", 카드 "✓ 적용됨" 잠김, 루틴 화면 리렌더+배지. 집중 모드에서는 focus 헤더의 작은 코치 아이콘으로 동일 챗 진입.

## 8. 구현 로드맵

구현 순서 제약: **기록 모델(Phase 1)이 챗(Phase 2)보다 반드시 선행** — 위치 기반 체크 키(`"sIdx-setIdx"`)를 날짜 키 세션 로그로 교체해야 오버라이드(세트 추가/삭제)가 진행 중 체크를 깨뜨리지 않는다.

### Phase 1 — 기록 기반 (서버·LLM 없음, +~500줄) → 단독 배포 가능
- 라우터 경로 테이블 교체 + 탭 3개 재편 + day 칩 스트립 (요구 C)
- 체크=목표 자동 기록, 실측 편집 시트, FOCUS "다르게 했어요" (요구 A)
- 날짜 키 SessionLog + 기록 탭 월 달력 + 세션 상세 (요구 B)
- *이날부터 LLM 기능의 원료(기록)가 쌓이기 시작 — 가장 먼저 해야 하는 이유.*

### Phase 2 — 서버 + 당일 조정 챗 (+~400줄 + Worker ~100줄)
- CF Worker 프록시 (토큰 해시 인증 + CORS 고정 + 파라미터 서버 고정 + mode 3종)
- FAB + 풀스크린 챗 (비스트리밍, JSON 봉투), diff 카드, 오버라이드 스냅샷 + 배지 + 되돌리기
- 설정 탭에 디바이스 토큰 입력 UI
- *Phase 1 로그가 2~3주 쌓인 뒤라 히스토리 요약도 의미 있어짐.*

### Phase 3 — 블록 프로그램 + 빌더 (+~500줄)
- Program 객체(템플릿+linear_kg+디로드) + 주차 계산 렌더 + `WEEK n/m`
- 빌더 챗 (인테이크 → 생성 → 검증 → 미리보기 → 적용), 블록 아카이브
- `buildHistorySummary()` (요구 D 완성)

### Phase 4 — 백로그 (필요가 증명되면)
IndexedDB(저장량 80% 도달 시) / SSE 스트리밍(빌더 대기가 고통일 때) / function calling(봉투 파싱이 말썽일 때) / percent·weekOverrides 진행 규칙 / e1RM 가드레일 / 코치 탭 대시보드 / 주 뷰 달력 / KV rate limit / 챗 영속 / 1일 복수 세션 / **서버 동기화 + SwiftUI 네이티브 전환**

매 배포 시 체크: `service-worker.js` 캐시 버전 bump (현행 v9 관례 유지).

예상 총량: Phase 1~3 합계 ~1,400~1,800줄 + Worker ~100줄. 단일 파일 PWA 유지 가능.

## 부록 — DeepSeek API 핵심 팩트 (2026-06-11 조사)

- Base URL `https://api.deepseek.com` (OpenAI 호환, `/chat/completions`), 인증 `Authorization: Bearer`
- `deepseek-v4-flash`: 1M 컨텍스트 / 384K 최대 출력 / $0.14 입력(캐시 히트 $0.0028) / $0.28 출력 per 1M tokens
- `deepseek-v4-pro`: $0.435 / $0.87 (상위 모델)
- thinking 모드: `{"thinking": {"type": "enabled"|"disabled"}}`, 기본 enabled. thinking 중 temperature 무시됨
- JSON 모드: `response_format: {type:"json_object"}` + 프롬프트에 "json" 단어와 형식 예시 필수
- 컨텍스트 캐시: 자동(prefix 완전 일치), usage에 `prompt_cache_hit_tokens`/`prompt_cache_miss_tokens` 보고
- Rate limit: 동시성 기반(flash 2,500 동시 요청) — 개인 사용에선 무관
- 스트리밍: SSE 지원 (`stream: true`) — v1 미사용
